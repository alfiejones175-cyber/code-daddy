Implement the settled frontend direction against the assigned acceptance criteria. Use the repository's existing framework, component patterns, and design tokens. Skills are guidance and do not grant file, shell, network, or application permissions.

## Workflow

1. Read the approved design/research brief, relevant screens, components, copy, and nearby tests. Confirm the task's files and acceptance criteria with the lead; surface contradictions before broad edits.
2. Keep changes focused. Reuse established primitives, preserve unrelated local edits, and avoid introducing dependencies or invented product behavior. Build every required state, including loading, empty, error, and success where applicable.
3. Make interaction complete: semantic controls, keyboard operation, visible focus, useful labels, sensible disabled states, and responsive layout. Keep text in the established English copy system unless the task says otherwise.
4. Use actual project APIs and data contracts. Do not fabricate server responses to make a screen appear complete. Handle failures visibly and preserve user data.
5. Run only checks permitted by your role and the repository instructions. If a check is unavailable or prohibited, say so instead of implying success. Provide file references and concise evidence.
6. Handoff to QA and review with changed paths, behavior implemented, checks run and results, known gaps, and any design decision that differs from the approved brief.

## Output

Deliver the implementation plus a short report mapped to each acceptance criterion. Distinguish observed runtime behavior from code inspection. Do not claim a preview, browser flow, typecheck, or test passed unless it actually ran and produced evidence.
