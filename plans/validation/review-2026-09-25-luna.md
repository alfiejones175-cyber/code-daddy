## Findings

1. **P2 — Composer controls collide in the split review layout.** Mac-observed in the native app: with the review panel open, the composer’s “Default” variant control and the green send button visibly overlap at the right edge in screenshots 08–11. This can make either control harder to target. Source context: the composer places controls and submit in one toolbar row (`packages/session-ui/src/v2/components/prompt-input/index.tsx:202`), while the session layout keeps a 450 px minimum chat panel and reserves 800 px for split review (`packages/app/src/pages/session/session-panel-width.ts:5`). The exact CSS viewport and click behavior were not measured. **Acceptance:** repeat at the same split layout and confirm each control has a distinct visible and clickable area at the smallest supported width.

2. **P2 — Disabled Auto-accept has no visible reason.** Mac-observed in General settings: the control is disabled, while its description says permission requests will be automatically approved; no reason or next step is shown. Source confirms it is disabled when no directory is available (`packages/app/src/components/settings-general.tsx:322`). **Acceptance:** explain why it is disabled and provide a clear route to a directory/session context; keep the control unavailable until that context exists.

3. **P2 — V1-only feature pages stop at an unsupported message.** Mac-observed in Capabilities and Routines: Capabilities says “Connect to a V2 server to use this workspace,” and Routines says “Routines require a V2 server.” Neither screen shows a direct path to the Servers settings. Routines also presents scheduling caveats before explaining that the current server cannot use the feature. Source anchors: `packages/app/src/components/settings-capabilities.tsx:90`, `packages/app/src/components/settings-v2/routines.tsx:103`, and the English copy in `packages/app/src/i18n/en.ts:40` and `packages/app/src/i18n/en.ts:1207`. The roadmap documents that the installed desktop defaults to V1 (`plans/README.md`). **Acceptance:** lead with the current limitation and link to the server setup that can resolve it, or clearly state that V2 is not available in this installation.

4. **P3 — OpenCode Zen connection status may confuse free-model access.** Mac-observed: Settings → Providers shows OpenCode Zen with a “Connect” button, while the model selector lists four Zen models as Free and Muse Spark 1.3 Free is already selected. Source/docs describe an OpenCode public/no-key model path (`plans/README.md`); the free selector code requires explicit zero costs for all tiers (`packages/app/src/components/free-model.ts`). No request was sent, so access was not live-verified. **Acceptance:** clarify whether Zen connection is optional for these public free models, and verify any access limits separately without a paid fallback.
